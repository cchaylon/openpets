# 本地运行环境

面向二次开发（改应用、做宠物包），不是终端用户的安装说明。项目不需要数据库、Docker、
后端服务或插件市场；内置宠物随应用提供，离线可用。

## 一、必须项

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows / macOS / Linux 桌面版 | 需要图形会话；透明置顶窗口依赖桌面合成器 |
| Node.js | `>= 20` | 根 `package.json` 的 `engines` |
| pnpm | `11.0.8` | `packageManager: pnpm@11.0.8`，建议用 Corepack 自动匹配 |
| 图形会话 | 必需 | 无 `DISPLAY` / 无桌面环境的 SSH 会启动失败 |

`electron`、`sharp` 都提供预编译产物，正常安装**不需要**本机 C++ 编译器、Python 构建链或 `npm rebuild`。

## 二、一次性准备

```bash
corepack enable
pnpm install
```

Electron 二进制在安装阶段下载；首次安装失败通常是网络或镜像问题，设置 `ELECTRON_MIRROR` 后重试：

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
pnpm install --registry=https://registry.npmmirror.com
```

## 三、平台差异

### Windows

- 开发无需 Visual Studio Build Tools。
- pnpm 的 workspace 链接需要创建符号链接的能力：打开「开发人员模式」或以管理员身份运行终端，
  否则会报 `EPERM: operation not permitted, symlink`。
- 应用图标为 `.ico`，安装包为 NSIS。

### macOS

- 日常开发只需 Node + pnpm；只有本地打包才需要 Xcode Command Line Tools：`xcode-select --install`。
- 应用会隐藏 Dock 图标（`app.dock.hide()`），只能从托盘或宠物交互进入。
- 宠物窗口设置了 `setVisibleOnAllWorkspaces`，可在全屏应用上方显示。

### Linux

- 需要能正确合成的桌面环境，否则透明窗口可能显示为黑色矩形。
- Wayland 会话下窗口定位与置顶由合成器策略决定；需要在 X11 / XWayland 会话中获得一致行为。
- 运行库（Debian / Ubuntu 系，Ubuntu 24.04 部分包名带 `t64` 后缀）：

  ```bash
  sudo apt-get install -y \
    libgtk-3-0 libnss3 libasound2 libgbm1 libdrm2 \
    libxss1 libxtst6 libx11-xcb1 libxkbcommon0 \
    libxcomposite1 libxdamage1 libxrandr2 libcups2 \
    libatk1.0-0 libatk-bridge2.0-0 libpango-1.0-0 libcairo2
  ```

- Electron 的 `chrome-sandbox` 需 root 所有且权限 `4755`，否则报 `SUID sandbox helper` 错误；
  本地开发可临时加 `--no-sandbox`（不要用于发布构建）。

## 四、开发环境变量

只有一个可选变量，在启动命令前设置即可。

| 变量 | 作用 |
| --- | --- |
| `DESKPET_RENDERER_URL` | 让控制中心加载 Vite 开发服务器（`dev:desktop:control-center` 自动设为 `http://127.0.0.1:5173`） |

`dev:desktop:control-center` 会占用 `127.0.0.1:5173`，端口被占用时需先释放。
开发期 CSP 会在 `vite.config.ts` 中自动追加 `http://127.0.0.1:5173` 与 `ws://127.0.0.1:5173`。

## 五、常用命令

```bash
pnpm dev:desktop                 # 构建主进程 + 前端，然后启动 Electron
pnpm dev:desktop:control-center  # 前端热更新（Vite 5173 + Electron）
pnpm build                       # 只构建，不启动
pnpm check                       # 两套 tsconfig 类型检查 + 完整构建
pnpm package:desktop             # electron-builder 打包
```

只改主进程时可跳过前端构建：

```bash
pnpm --filter @deskpet/desktop dev:electron
```

## 六、启动与验证

启动成功的标志：

1. 托盘出现图标；
2. 桌面右下角出现宠物（默认 `showOnLaunch: true`）；
3. 日志出现 `{"level":"info","scope":"app","message":"ready",...}`。

日志与状态位置（应用名 `DeskPet`）：

| 平台 | 目录 |
| --- | --- |
| Windows | `%APPDATA%\DeskPet\` |
| macOS | `~/Library/Application Support/DeskPet/` |
| Linux | `~/.config/DeskPet/` |

- 日志：`logs/deskpet.log`，超过 2 MiB 轮转为 `deskpet.log.1`
- 状态：`deskpet-state.json`
- 宠物：`pets/<id>/`

`pnpm dev:desktop` 会先执行完整构建，首次启动明显更慢；之后只改主进程可用 `dev:electron`。

提交前建议：

```bash
pnpm check
git diff --check
```

## 七、常见阻塞

| 现象 | 处理 |
| --- | --- |
| `pnpm install` 报 `EPERM: symlink` | 开启 Windows 开发人员模式，或以管理员身份运行终端 |
| 安装或首次启动卡在下载 Electron | 设置 `ELECTRON_MIRROR`（必要时加代理）后重装 |
| `sharp` 安装失败 | 换 `registry.npmmirror.com` 重试，避免源码编译 |
| `Missing X server or $DISPLAY` | 在无图形会话的 SSH 中启动；改到桌面会话运行 |
| 宠物窗口透明区域为黑色 | Linux 桌面缺少合成器 |
| 控制中心提示「请在 DeskPet 应用内打开控制中心」 | 控制中心依赖 preload，必须从托盘 / 双击宠物打开，不要用浏览器直接访问 `dist/renderer/index.html` |
| 5173 端口被占用 | 释放端口后重新执行 `pnpm dev:desktop:control-center` |
| 新增图片协议后图片不显示 | 同时更新 `src/renderer/index.html` 与 `vite.config.ts` 两处 CSP 的 `img-src` |
| 想恢复默认设置 | 退出应用后删除 `deskpet-state.json`；宠物文件在 `pets/` 目录单独删除 |

宠物导入失败时，错误信息会直接显示在控制中心 Toast 中，常见原因见
[项目工程结构](项目工程结构.md) 的「宠物包格式」一节。
